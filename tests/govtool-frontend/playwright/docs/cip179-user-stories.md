# CIP-179 linked surveys

User stories follow the maintainer's [User Story / Acceptance Criteria format](https://docs.google.com/document/d/1gtPb3tzQqPzP064R48Nbz2gRuwtT8XPLJIr5ju9INWQ/edit), requested in [PR #4184](https://github.com/IntersectMBO/govtool/pull/4184#issuecomment-5676184783).

## Governance-action authoring (connected wallet)

| User Story                                                                                                                                                | Acceptance Criteria                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **179-1A.** As an action author, I want to optionally link an existing survey, so voters can answer it without mixing its questions into the action body. | **Given** a connected wallet and an Info Action with title, abstract, motivation and rationale, **when** I download its metadata with a valid survey transaction ID, **then** the CIP-108 body preserves those sections and includes a normalized CIP-179 v5 link to survey index 0; survey questions are not copied into the body. **When** I leave the field empty, **then** the metadata has no survey link or CIP-179 context and no survey lookup is made. |
| **179-1B.** As an action author, I want malformed survey references rejected before proceeding.                                                           | **Given** a completed action form, **when** I enter a transaction ID that is not 64 hexadecimal characters, **then** Continue is disabled. **When** I clear this optional field, **then** Continue is enabled again.                                                                                                                                                                                                                                            |
| **179-1C.** As a deployment operator, I want to be able to disable survey authoring.                                                                      | **Given** `VITE_IS_CIP179_ENABLED=false`, **when** an author opens the action form, **then** the survey field is absent and ordinary action authoring remains available.                                                                                                                                                                                                                                                                                        |

## Voting (registered DRep)

| User Story                                                                                            | Acceptance Criteria                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **179-2A.** As a DRep, I want to include public survey answers with my governance vote.               | **Given** a valid linked survey and the default feature configuration, **when** I opt in, select an option and a bounded numeric answer, and submit, **then** label 17 contains one v5 response with the exact survey reference, DRep credential, question indexes and answers. The governance vote, auxiliary-data hash, metadata and valid witness survive signing and submission. |
| **179-2B.** As a DRep, I want survey participation to remain optional.                                | **Given** an action without a survey, a deployment with the feature disabled, or a survey I have not opted into, **when** I submit an ordinary vote, **then** the normal vote and signature are preserved without survey metadata. Disabled/unlinked cases make no survey request.                                                                                                   |
| **179-2C.** As a DRep, I want required answers enforced and cleared optional answers omitted.         | **Given** an opted-in survey with required and optional questions, **when** required answers are missing, **then** attempting submission never requests a wallet signature. **When** I answer the required question and clear an optional numeric answer, **then** submission includes only the required answer.                                                                     |
| **179-2D.** As a DRep, I want numeric controls that cannot produce out-of-range or imprecise answers. | **Given** bounded numeric questions, **when** I use the controls, **then** there is no editable numeric textbox, bounds and steps are enforced, zero requires explicit selection, negative minima and unaligned maxima remain valid, a single-value range requires selection, and integers beyond JavaScript's safe numeric precision remain exact in submitted metadata.            |
| **179-2E.** As a DRep, I want each supported question type to preserve its meaning.                   | **Given** single-choice, multi-select, ranking, numeric rating, label rating and points-allocation questions, **when** I answer them, **then** selection limits and the exact points budget are enforced; ranking follows selection order; zero ratings are preserved; unrated optional items are omitted; and metadata contains the correct method tags and indexes.                |
| **179-2F.** As a DRep, I want sealed answers encrypted before wallet signing.                         | **Given** a quicknet sealed survey, **when** I answer and submit, **then** label 17 contains ciphertext rather than public answers, signing preserves it, and decrypting with the corresponding fixture beacon recovers precisely the selected answers and expected padding.                                                                                                         |

## Unavailable data, eligibility and failures

| User Story                                                                                                           | Acceptance Criteria                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **179-3A.** As a DRep, I want a bad survey to leave ordinary governance voting usable.                               | **Given** an unavailable definition, mismatched transaction reference, mismatched expiry, or more than 100 questions, **when** I view the action, **then** an unavailable-survey warning replaces participation controls and an ordinary vote still signs and submits without survey metadata.                                         |
| **179-3B.** As a DRep, I want participation limited to the survey's eligible roles.                                  | **Given** a survey that excludes DReps, **when** I view it, **then** the page explains the restriction and offers no survey opt-in, while ordinary voting still works.                                                                                                                                                                 |
| **179-3C.** As a voter, I want wallet rejection to cancel submission.                                                | **Given** completed survey answers, **when** I decline wallet signing, **then** GovTool shows an error and never calls wallet submission.                                                                                                                                                                                              |
| **179-3D.** As a disconnected or non-DRep visitor, I want to view actions without being offered a DRep signing flow. | **Given** either state, **when** I open the action, **then** its title renders but the vote submission button is absent and no signing occurs.                                                                                                                                                                                         |
| **179-3E.** As a DRep, I want external presentation data checked before it changes survey labels.                    | **Given** a count-based survey with a content anchor, **when** the presentation has a matching hash and valid fields, **then** its labels render. **When** its hash or fields are invalid or the download fails, **then** a warning and index-based fallback labels render; valid answers can still be submitted without a page error. |
| **179-3F.** As a DRep, I want to answer supported questions even if an optional custom method is unavailable.        | **Given** an optional unregistered custom method, **when** I answer the supported required question, **then** GovTool explains the unsupported method and submits only the supported answer.                                                                                                                                           |

## Automated coverage and running locally

Every story ID above appears in the corresponding test title in [authoring.spec.ts](../tests/cip179/authoring.spec.ts) or [survey.spec.ts](../tests/cip179/survey.spec.ts). Parameterized cases run in both desktop Chromium and mobile Chromium. The normal funded-wallet test configuration excludes this suite; the dedicated configuration starts the actual frontend itself.

From the repository root, using the frontend's `.nvmrc` Node version:

```sh
npm ci --prefix govtool/frontend
npm ci --ignore-scripts --prefix tests/govtool-frontend/playwright
cd tests/govtool-frontend/playwright
PLAYWRIGHT_BROWSERS_PATH="$PWD/.browsers" npx playwright install chromium
PLAYWRIGHT_BROWSERS_PATH="$PWD/.browsers" npm run test:cip179
```

An existing Chromium binary can instead be selected with `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Dependencies, browser downloads, traces and screenshots can all remain inside the checkout. The frontend CI workflow runs this suite and uploads failure artifacts.

The tests use real UI components, hooks, transaction construction, encryption and signature verification. HTTP responses and CIP-30/CIP-95 wallet calls are simulated; external network requests are blocked. The test key and UTxO are public fixtures and must never be funded. The historical drand round is deliberately decryptable for offline assertions; real sealed surveys need a suitable future round. These tests do not validate backend indexing, real wallet extensions/hardware, live IPFS, or chain acceptance. Existing unit tests cover additional codec, presentation-size, index and numeric edge cases.

Live Preview smoke-test evidence supplements this deterministic suite:

- [Contributor vote](https://preview.cexplorer.io/tx/198b25ef1feb61f4f3473dd436381d1f01a75dc0c1fd1a621f55720ece7ea9d3): public survey metadata independently inspected during development.
- [Maintainer vote](https://preview.cexplorer.io/tx/39ff0407bdb0aad066832c80af1d610c03d6fe9441f509e3a522e05a82c9a4f2): successful flow reported in the linked review comment.

CIP-179 is enabled when the flag is omitted, both in development and the container entrypoint. Set `VITE_IS_CIP179_ENABLED=false` explicitly to opt out. Survey answering still requires the voter to opt in individually.
